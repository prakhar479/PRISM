# Reproducing the results

Three levels, from cheapest to most expensive:
1. Regenerate tables and figures from the released run outputs: CPU only, minutes.
2. Check the code: unit and end-to-end tests with a tiny random model, CPU, about 5 minutes.
3. Re-run the experiments: GPUs, on the order of 150 GPU-hours in total (estimated from the queue logs).

## Environment
- **Exact versions:** use Python 3.12 and the lock file `requirements/harness.lock`, generated by `uv pip compile`.
  `requirements/harness-cu126.lock` is the same with a CUDA 12.6 torch build.
- **Install** (the lock pins torch 2.14.1+cu130; that wheel also runs on a machine without a GPU):

  ```bash
  python3.12 -m venv .venv
  .venv/bin/pip install uv
  .venv/bin/uv pip sync --python .venv/bin/python requirements/harness.lock --index-strategy unsafe-best-match \
      --extra-index-url https://download.pytorch.org/whl/cu130
  ```
- **GPU servers:** `scripts/setup_server.sh` does the same and also reassembles the golden fixtures.
- **Looser alternative:** `requirements.txt` gives minimum versions.

## 1. Tables and figures from `results/runs`
Run everything from the repository root. `profiles/dev.yaml` points the analysis at `results/runs`.

| output | command | inputs |
|---|---|---|
| `tables/RQ1_gate.*` (preregistered gate) | `python scripts/make_gate.py --only E0,E1,E2,E3,E4,E5,E6,E7` | E0–E7 (the set that existed when the gate was read) |
| `tables/E8_*` (atlas, specificity) | `python scripts/make_e8.py --only E0,E1,E2,E3,E4,E5,E6,E7,E8` | E0–E8 |
| `tables/E4_width_persistence.csv` | `python scripts/make_e4.py` | E4 |
| `tables/E0_*`, `E3_*`, `E4_width_l0`, `E5_*` | `python scripts/make_tables.py --only E0,E3,E4,E5` | |
| `tables/final/E12_fidelity_lang.csv` | `python scripts/make_e12.py --runs results/runs --out tables/final` | E12 (+ E21 65k runs) |
| `tables/final/E13_behaviour_lang.csv` | `python scripts/make_e13.py --runs results/runs --out tables/final` | E13 |
| `tables/final/E9…E22_*` | `python scripts/make_final.py --runs results/runs --out tables/final` (`--only E9,E10,...` for a subset) | E9–E22; reads E13's table for the gates |
| `paper/figures/F1–F7` | `python analysis/team/scripts/fig_F<n>_*.py` (written to `analysis/team/figures/`); run `analysis/team/scripts/multilingual_load.py` and `analysis/team/scripts/lead_capture.py` first | `tables/`, `analysis/team/*_out/` |

**Checked on this release:**
- `make_gate.py` reproduces `tables/RQ1_gate.csv` exactly.
- `make_e8.py --only E0,…,E8` reproduces `tables/E8_gaps.csv`, `E8_shares.csv` and `E8_allcells.csv` byte for byte.
- `make_e12.py` reproduces `E12_fidelity_lang.csv` byte for byte.
- `make_final.py --only E9` reproduces `E9_conditions.csv` and `E9_illusion.csv` value for value (row order aside). It also
  adds one column, `das_init_capture`, introduced after those tables were frozen.
- All seven figure scripts reproduce the plotted data in `paper/figures/*_data.csv` byte for byte.

**Bootstraps:** they use fixed seeds (10,000 resamples, seed 0), so regenerated CIs are identical.

## Exploratory analysis scripts
- **Where they are:** `analysis/team/scripts/` and `analysis/deep/scripts/` hold the scripts behind the exploratory reports.
- **The layout shim:** they were written against a scratch workspace layout. `layout_shim.py` (next to them) recreates it
  with symbolic links under `.layout/`, which is git-ignored, so the scripts run unchanged from the repository root.
- **Decoders:** the geometry scripts also need two public Gemma Scope decoders: `bash scripts/fetch_decoders.sh`.
- **Coverage:** the figure scripts, `lead_capture.py` and `multilingual_load.py` were re-run on this release. The other
  exploratory scripts are archived as run; their outputs are the CSVs and logs next to them (`*_out/`).

## 2. Tests
```bash
python -m pytest -q tests        # ~200 tests, tiny random model, no GPU, no downloads
```
`tests/harness/test_prereg_frozen.py` pins the hashes of the frozen preregistration documents.

## 3. Re-running experiments
- **Requirements:** NVIDIA GPUs with ≥ 11 GB each (the runs used RTX 2080 Ti nodes), and a Hugging Face token with access to
  the gated gemma-2-2b.
- **What a queue does:** `scripts/run_queue.py --queue queue/<name>.yaml --gpus auto` runs prefetch, a per-GPU preflight
  (regression against the golden fixtures and the pilot), stages 1–3 and finalize, then bundles the results.
- **Procedures:** `scripts/slurm_final.sbatch` and `docs/FINAL_PASS_RUNBOOK.md` / `docs/FINAL_EXPLORE_RUNBOOK.md`.
- **Which queue made which runs:**

| queue | experiments |
|---|---|
| `queue/release1.yaml` | E0, E1, E2, E6, E7 (development laptop GPU) |
| `queue/release2-server.yaml` | E3, E4, E5, E8 |
| `queue/complete-server.yaml` | E9, E9b, E10, E10b, E11, E12–E14, E16, E2r |
| `queue/final-explore-server.yaml` | E17–E22 and E21 (as E12 runs); E23 is defined there but was not run |

- **Comparing a new run:** a run's `run_hash` is a hash of its configuration and inputs, so a re-run lands in the same
  `results/runs/<exp>/<hash>` path and can be compared file by file.
- **Expected agreement:**
  - outputs are bit-identical across nodes with the same GPU model;
  - on a different GPU architecture, headline gaps agreed within about 0.7 points.
